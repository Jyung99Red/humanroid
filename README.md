# 人形走路：GPU 上的强化学习 + three.js 回放

21 个关节的 3D 人形，从不会站开始，用 PPO 在 GPU 上并行训练（4096 个人形同时跑），学会稳定行走。
训练结果导出成轨迹，在浏览器里用 three.js 回放，可以把不同训练阶段并排对比。

## 怎么用
命令都用项目自带的虚拟环境；Windows 下加 `PYTHONUTF8=1`，否则管道输出中文会因 cp1252 报错。

```
.venv\Scripts\python.exe make_model.py human50                          # 生成身体模型 models/human50_pd.xml（只需一次；不带参数是官方身体 humanoid_pd.xml）
.venv\Scripts\python.exe check_body.py models/human50_pd.xml            # 体检：质量分布、力气、活动范围、起跳测验
.venv\Scripts\python.exe find_arm_pose.py                               # 算手臂下垂的关节角 → models/arm_pose.json（只需一次）
.venv\Scripts\python.exe train.py --xml models/human50_pd.xml --iters 1500 --out runs/xxx   # 训练，每轮约 0.7 秒
.venv\Scripts\python.exe train.py --resume runs/walk1/ckpt.pt --iters 500 --out runs/walk1   # 续训
.venv\Scripts\python.exe export.py runs/walk1/policy.pt --worlds 6      # 导出回放到 web/replays/（--cmd vx,vy,wz  --gait 步频,着地比例）
.venv\Scripts\python.exe export.py runs/xxx/policy.pt --steps 700 --seq "0:1.0,0,0; 4:0,0,0,0.925,1; 6.5:-0.4,0,0"   # 按时间换指令(秒:vx,vy,wz[,步频,着地比例]): 走 -> 站定 -> 倒退
.venv\Scripts\python.exe export_timeline.py runs/sp2 --name sp2 --solo   # 整条训练链的所有快照导出成时间线, 回放页面拖"轮数"逐个看; --solo 列表只留它, 其他回放归档
.venv\Scripts\python.exe eval_policy.py runs/xxx/policy.pt              # 测跟指令: 实际步频、着地比例、速度
.venv\Scripts\python.exe regress.py runs/新/policy.pt --baseline runs/旧/regress.json --save   # 回归测验, 和基线比
.venv\Scripts\python.exe foot_phase.py runs/xxx/policy.pt              # 按步态时钟分 10 段, 左右脚各自的俯仰(脚跟着地/踩平/蹬地对不对)
.venv\Scripts\python.exe check_mirror.py runs/xxx/policy.pt             # 检查身体/观测/奖励左右对称、镜像映射写对; 顺带量策略多不对称
viewer.bat                                                              # 起本地服务并打开回放页面(页面左上角"互动版 →"进网页互动版)
.venv\Scripts\python.exe export_web.py --walk runs/sp2/policy.pt --getup runs/getup7/policy.pt   # 导出网页互动版用的两个策略 → web/play/policies.json
.venv\Scripts\python.exe cpu_check.py                                   # 网页互动版的参考实现: 在 MuJoCo CPU 版里跑站/走/推/起身, 确认策略换了引擎也能用
.venv\Scripts\python.exe cpu_check.py --balls                           # 发球机测验: 每种球打躯干/头, 命中率和被打倒的比例
.venv\Scripts\python.exe move_probe.py                                  # 起步多快: 站着突然给侧移/倒退/前进指令, 0.3/0.5/0.8 秒挪开多远(网页用的策略, CPU 版)
.venv\Scripts\python.exe test_dodge.py runs/xxx/policy.pt --ball steer=1      # 躲球测验: 开着发球机站着/走着, 几档球速下被打中的比例和摔倒
.venv\Scripts\python.exe reward_terms.py runs/xxx/policy.pt --cmd 0,0.4,0 --obs-cmd 0,0.8,0   # 奖励分项; --obs-cmd = 反事实: 按另一个指令走, 奖励按 --cmd 算
```
- 训练日志：每轮一行，同时写 `runs/<名>/train_log.csv`。每 10 轮存 `ckpt.pt`（续训）和 `policy.pt`（回放），每 50 轮存快照到 `snaps/`（`--snap-every`，每个约 330 KB，导出成时间线后约 0.5 MB；5000 轮约 100 个快照，硬盘 33 MB + 回放 50 MB）。
- 回放：`export.py` 可导出任何快照；网页里勾选多个即同台对比。链接参数 `?r=文件1,文件2&t=秒&pause=1` 直达某个时刻。
- 时间线：`export_timeline.py` 把一条训练链（顺着 `config.json` 的 `resume` 往回找）的所有快照用同一串指令跑一遍，网页里拖"轮数"滑块或按 ↑/↓ 逐个看，链接参数 `it=轮数`。再跑一次只补新快照。见"回放页面"。
- 奖励不改代码调：`--rw clock=0.5,alive=0.1`；可用项见 `env.py` 顶部 `REWARD`。
- 左右镜像约束：`train.py --sym 4`（见"设计要点"）。新加观测块要在 `env.HumanoidEnv._mirror_block` 写它的镜像，否则开了 `--sym` 会报错。
- 随机推搡 `--push 150 --push-period 2,5`：每 2～5 秒给躯干一个随机方向的水平力，大小 0～150 N，持续 0.2 秒；评论家加 `--priv-add push` 看到当前推力。见"阶段 1d"。
- 起身（见"阶段 1f"）：`train.py --getup --full-range --assist 0.6`；测验 `test_getup.py`；回放 `export.py runs/sp2/policy.pt --getup runs/getup6/policy.pt --lying 0.5`（倒地开局、两个策略切换）。
- 导出时推：`export.py ... --push "2:0,-150; 5:-150,0"`（秒:fx,fy，世界系、牛，x 朝前、y 朝左），网页上推的时候画红色箭头。`export_timeline.py` 也有 `--push`。
- KL 目标 `--kl 0.02`（默认 0.01）：学习率按 KL 自动调，std 塌到 0.15 时学习率被压到 1.4e−5，调成 0.02 后升到 7.4e−5。
- 续训时重置探索噪声 `--std 0.3`（std 塌到 0.15 时策略几乎学不动，但放大噪声可能把已有技能冲掉，见"阶段 1c"）。
- 动作边界损失 `--bound 1`：动作均值超出"PD 目标角不被关节限位裁掉"的范围就罚（见"设计要点"）。
- 指令加速度限制 `--cmd-acc 1.5`、换指令间隔 `--cmd-period 1,5`（秒，每次随机抽），见"阶段 1b"。
- 指令范围：`--vx 0.4,1.2 --vy 0,0 --wz -0.3,0.3 --freq 0.75,1.1 --duty 0.5,0.7`（每个人形每 5 秒在范围里重抽一次）。不给 `--freq` 就固定为 1 / `--gait-period`。范围以负数开头要写成 `--vx=-0.6,1.2`，否则 argparse 当成选项报错。`--stand 0.15`：重抽时 15% 的概率是站定（速度全 0、着地比例 1）。
- 不给 `--arm-pose` 就是官方默认姿势（手臂斜向前伸）。
- 身体模型（`--xml`）、观测块布局和其他环境设置一起存进策略文件，`export.py` 回放时用同一套。不给 `--xml` 是官方身体。
- 给已训好的策略加新输入：`train.py --resume runs/xxx/ckpt.pt --obs-add 块名 --out runs/yyy`（只给评论家用 `--priv-add`）。可用块见 `env.py` 的 `OBS_BLOCKS`。

## 设计要点
- **GPU**：人形物理 4096 并行约 1.3M 步/秒，CPU 12 核理想上限约 0.49M。
- **物理引擎 MuJoCo Warp**（`mujoco-warp` + `warp-lang`）：原生 Windows + RTX 4060 直接跑，通过 `wp.to_torch` 和 PyTorch 共享显存。MJX 需要 JAX 的 GPU 版，Windows 上要走 WSL。
- **观测由有名字的块拼成**（`env.OBS_BLOCKS`）。默认演员 77 维：重力方向、线速度、角速度（机体系）、关节角、关节速度、上一步动作、速度指令（3）、步态时钟 sin/cos；评论家另看到躯干高度和两脚着地。
- **观测可扩展，加输入不用从头练**：检查点记着块布局 `[(名字, 维数), ...]`。续训时环境多了新块，`ppo.expand_checkpoint` 按块名重排演员和评论家的第一层权重，新块补零列，Adam 动量和归一化统计一起补。新输入一开始不起作用，已有行为不变：实测动作差 0、价值差 3e-5（价值约 124，是列重排导致的浮点误差）。只能加不能删，块的含义和缩放定了就别改，要改就加一个新块。
- **观测归一化每一维各自计数**：共用一个计数时训练久了计数到几千万，新加的维度几乎不更新；现在新维度从零开始计数，很快跟上。
- **从没变过的输入当新输入处理**（`ppo._revive_constant_inputs`，2026-10-15）：续训时检查点里方差几乎为 0 的输入维（例如一直是 0 的侧移指令），统计量重置、第一层对应的列和 Adam 动量清零。它们以前归一化后恒为 0，清零不改变已有行为。不处理的话：计数已经上亿，放宽指令范围后方差几乎不更新，新指令归一化后被放大到 ±10，再乘上从没训练过的随机权重。实测 stand3 收到侧移指令时一个方向 100 个全摔、另一个方向不摔也不动（镜像约束只管见过的数据，没见过的输入不保证对称）。
- **动作 = PD 位置目标**：策略输出每个关节想去的角度，底层 PD 追（`kp = 2×gear`、`kv = 0.1×gear`，力矩限 ±gear，gear 即最大力矩，见"身体模型"），每个策略步 4 个物理步（50 Hz）。
- **默认姿态加幅度**：目标角 = 站直姿态 + 动作 × (0.3 × 关节范围)，动作裁到 ±1.5。不直接映射整个关节范围：髋关节中点是 −65°，起点会是怪姿势。
- **局部重置自写**（`env.reset_idx`）：`mjw.reset_data` 每次调用新建 kernel，每步调太慢。
- **接触池显式设大**（`nconmax=64, njmax=160`）：默认值在人倒地时容易超，超了不报错，只是悄悄丢约束。`env.diagnostics()` 的 `dropped_worlds` 必须为 0；`iter_limit_worlds` 是求解器迭代到上限，只是没完全收敛，猛甩时出现少量无妨。
- **手臂默认姿势**：PD 零点改成自然下垂（肩 34.6°/−23.4°、肘 −90°，左右对称），手臂动作幅度减半，加小的偏离惩罚 `arm_dev`。改的是默认姿势，换姿势要重训。
- **摆臂靠奖励引导**（`arm_swing`）：手臂目标 = 默认姿势 + 随步态时钟前后摆，与同侧腿反相，幅度正比于指令速度，指令 0 时即默认姿势。奖励 `exp(−六个手臂关节偏差平方和 / 0.15)`，肘不动。肩的两根轴是斜的，"往前摆"对应的两肩转角由 `arm_swing_dirs` 数值求出（每弧度：shoulder1 −0.377、shoulder2 +0.910）。观测不变，可从 `walk2` 续训。`arm_dev` 惩罚离开固定姿势，与 `arm_swing` 冲突，用后者时设 0。
- **指令 = 速度 + 步态，站/走/跑统一**：速度 `(vx, vy, wz)` 加步态 `(步频 f, 着地比例 D)`。步态时钟按 f 走（一个周期左右各一步，步数/分 = 120 f）；`clock` 奖励要求右脚在时钟 `[0, D)` 踩地、左脚晚半个周期。D = 0.5 左右严格轮换（旧策略唯一的模式，旧配置的行为不变），D > 0.5 有双脚支撑是走，D < 0.5 有腾空是跑，D = 1 两脚一直踩地是站（`--stand` 按概率抽到）。步态作为观测块 `gait` 给演员（从头训练默认带上，旧检查点用 `--obs-add gait` 加）。
- **步子大小由步频决定**：同样速度下步长 = 速度 / (2 f)。旧的 `--gait-period` 就是 1 / f：0.8 秒是 150 步/分（1 m/s 时步长 0.4 米，碎步），1.1 秒是 109 步/分（步长 0.5 米出头，近似慢走）。真人慢走约 100～115 步/分、着地比例约 0.6，跑步约 160～180 步/分、着地比例约 0.3～0.4。
- **脚的姿态要单独约束**：不约束时策略怎么省事怎么踩（脚内翻、脚尖朝内、踩地打滑）。三项惩罚：`foot_roll`（脚左右翻转，放平为 0）、`foot_yaw`（脚尖偏离前进方向）、`foot_slip`（着地脚的水平速度）。前后俯仰不罚，保留脚跟先着地、脚尖蹬地。
- **摔倒 = 脚以外的部位碰地**（`env.ground_contact`）：每步扫一遍接触池（所有世界共用，前 `nacon` 个有效），按 geom 所属刚体分成右脚、左脚、身体其他部位、地面，用 `bincount` 汇总到各世界，全在 GPU 上，约 0.6 ms / 步（整步约 15 ms）。不看高度和倾角，所以深蹲、弯腰躲闪、落地缓冲都不算摔；臀、膝、手、头碰地都算。只看每个策略步最后一个物理步的接触，短于 20 ms 的轻触可能漏掉。
- **脚是否着地也用真实接触**：同一次扫描得到。以前用"脚踝高度 < 5.5 cm"估算，和真实接触只有 71% 一致（脚尖蹬地时估算说离地、脚刚抬起时估算还说着地，各占约 14%）。步态时钟奖励 `clock`、打滑惩罚 `foot_slip` 和评论家都用它。
- **姿态奖励（看起来像人）**：只给"跟指令 + 别摔"时，策略会用最省事的方式走，看起来不像人。下面几项各管一件真人会自然守住的事，默认都是 0，用 `--rw` 打开：
  - `head_level`：头保持水平、朝前（罚头相对地面的倾斜和脖子左右转）。不加时头俯仰晃 ±12°、平均偏 7.5°；加 5 后 ±1°。
  - `waist_twist`：罚腰的左右扭和侧弯（骨盆相对胸口）。不加时骨盆扭转 ±15～18°（walk4 也有），是策略用扭胯廉价地拉长步子。
  - `pelvis_level`：罚骨盆相对地面左右侧倾。不加时侧倾 ±14～15°，就是"模特扭胯"；`waist_twist` 罚得太轻压不住，策略宁可付代价用骨盆侧摆转移重心。
  - `step_width`：两脚间距小于 8 cm 开始罚。不加时落地两脚只隔 3～4 cm，踩一条线。
  - `foot_clear`：步态时钟说该摆动的脚，抬起高度要跟上 5 cm × sin(π × 摆动进度)。改用真实接触后脚擦地也算"抬起"，不加时抬脚只有 4～5 cm。目标定成 10 cm 会逼出踮脚走（骨盆不许侧摆又要抬高脚，就把支撑腿踮起来变长）。
  - `heel_down`：每次着地的前 70%（按步态时钟）罚脚尖朝下，即脚跟要踩实；最后 30% 留给蹬地，落地时脚尖朝上不罚。不加时着地才一半脚跟就抬起，后半段踮着走。
  - `toe_off`：每次着地的最后 30%、脚还踩着地时，脚跟抬起、脚尖压地给奖励（压到 20° 封顶）。只有 `heel_down` 时离地前不蹬地，用大腿直接把脚提起来。不要求"踩着地"的话，策略会在腿已经往前摆时还保持脚尖朝下拿奖励，脚尖就拖着地。
  - `point_slip`：脚跟点、脚尖点谁贴地（离地 < 1 cm）谁就不许水平移动。旧的 `foot_slip` 看脚中心的速度，蹬地时脚绕脚尖转、中心本来就动，它分不清"转"和"滑"，策略为了躲它干脆让脚尖蹭着走。新配方用 `point_slip`，`foot_slip` 设 0。
  - `swing_flat`：摆动中段（进度 25%～75%）罚脚相对地面前后倾斜。不加时摆腿把脚尖勾到 −31°。刚离地（脚尖朝下）和快落地（脚尖朝上准备脚跟着地）不管。
  - `foot_flat`：着地时罚脚尖翘着。`heel_down` 只罚脚尖朝下，所以策略可以让一只脚整个着地期都用脚跟走、脚尖一直翘着（style_trial6/7 的右脚，脚尖翘 25～45°）。前 20% 是脚跟着地，脚尖最多翘 20°（`LAND_TOE_UP`）；20%～70% 脚要踩平。和 `heel_down` 合起来就是"脚跟着地 → 踩平 → 蹬地"。
  - `heel_strike`：每次着地的前 15%、脚踩着地时，脚尖翘起给奖励（翘到 15° 封顶），和 `toe_off` 对称。实测对没有脚跟着地的那只脚不起作用：它落地时脚尖略朝下，奖励是 0、没有梯度。
  - `knee_swing`：步态时钟说该摆动的腿，屈膝要跟上 40° × sin(π × 摆动进度)（`KNEE_SWING_DEG`），弯得不够就罚。和 `foot_clear` 用同一个摆动进度，站定没有摆动期。
  - `knee_air`：同 `knee_swing`，但摆动进度 = 脚真正离地的时间 ÷ 指令的摆动时长（(1 − 着地比例) / 步频），不管什么时候抬脚要求都一样，抬脚时机只由 `clock` 管（见"阶段 1c"）。
  - `stand_feet`：指令是站定、又不在被推后 1 秒内时，哪只脚离地罚哪只。开了推搡后不加它，策略会学成"一直原地踏步"（见"阶段 1d"）。
  - `knee_lock`：膝盖弯得少于 5°（`KNEE_MIN_DEG`）就罚，伸直时罚满。不加这两项时 human50 的策略全程直腿走（见"阶段 1c"）。
  - **按指令区分往前走、倒退、站定**（阶段 1 加，`WALK_V = 0.3 m/s`）：上面这些规则是按往前走写的，站着时 `toe_off` 会周期性奖励踮脚、`heel_strike` 奖励翘脚尖。现在按前进速度指令混合三套：往前（速度 ≥ 0.3 时完全是这套，和以前一样）；倒退 = 往前走倒着放（前 30% 前脚掌先着地，`toe_off` 奖励这时脚尖朝下；最后 15～20% 脚跟最后离地，`heel_strike`、`foot_flat` 允许脚尖翘）；站定（速度 0）整个着地期踩平，不给蹬地和脚跟着地的奖励。摆臂幅度按带符号的速度，倒退时手臂反着摆，仍和对侧的腿同步。用同一个策略、同样的状态比过新旧代码的奖励，往前走时一致（差异和同一份代码跑两次一样，是 GPU 物理本身的不确定）。
  - 这些按步态时钟分段的项，本质上是在给走路写"关键帧"：规定每个相位该满足什么，不规定具体角度。阶段 1 打算换成动捕数据当风格老师（AMP），不用再一条条手写。
  - 为什么 walk4（D 版）不用这两项也走得像样：它训练时"着地"用"脚踝离地 < 5.5 cm"估算，踮脚或擦地走都会让脚踝越过 5.5 cm 而被当成"没着地"，节奏奖励扣分，等于间接逼着脚跟踩实、摆动时抬脚。改用真实接触后这两条隐含约束没了，要显式补上。
- **左右镜像约束**（`--sym`，2026-10-14 加）：身体、观测、奖励都左右对称时，最优策略本该对称，但网络不会自己保证，两条腿可能各学一套（style_trial6/7：右脚脚跟走、左脚前脚掌）。做法：
  - 镜像 = 关于躯干前后-竖直平面的反射。每个关节对应另一侧同名关节（躯干、脖子对应自己），变不变号由转轴算（转轴是赝矢量，镜像后 a → −Ma），站直时检查转轴和转动中心确实镜像（`env.mirror_joints`）。`human50` 四肢都不变号，`abdomen_z`、`abdomen_x`、`neck_z` 变号。
  - 观测块的镜像（`_mirror_block`）：重力、线速度的 y 变号；角速度是赝矢量，x、z 变号；速度指令的侧移、转向变号；步态时钟差半个周期（左脚就是晚半个周期的右脚），sin、cos 都变号；两脚着地互换。全部是"带符号的排列"。
  - 损失：演员加 `sym × |策略(镜像观测) − 镜像(策略(观测))|²`（各维求和）；评论家把镜像观测也学成同一个回报；探索噪声左右取平均。先镜像原始观测再归一化（归一化统计每维不同）。
  - `check_mirror.py` 验证（style_trial10 策略驱动 100 步）：观测差约 1e−5、奖励差约 2e−5，即身体、观测、18 项奖励都严格对称。style_trial10 自己的不对称是平均 0.47（动作单位）。
- **动作边界损失**（`--bound`，2026-10-16 加）：PD 目标角 = 默认姿势 + 动作 × 幅度，再裁到关节限位。动作超出"不被裁"的范围后，再怎么变目标角都一样，PPO 拿不到梯度，策略会永远卡在限位外。膝盖的伸直限位是 +2°，每单位动作 48.6°，动作大于 +0.04 就全是伸直；human50 的策略膝盖动作均值 +1.55～+3，探索噪声 std 0.16 根本够不回来，加了屈膝奖励也学不动（knee1 第一次试，150 轮膝盖纹丝不动）。所以对动作均值加 `bound × 超出量²`，把它拉回有梯度的范围。权重别太大：10 时 40 轮就拉回来，膝盖一下子解锁，策略乱了一阵，丢掉了站定和着地比例指令，700 轮都没恢复；1 时慢一些，站定保住了。
- **推搡**（`env.push`，2026-10-17 加）：推的是力，不是直接改速度，往 `xfrc_applied` 里给躯干写一个水平力，持续 `push_len` 步（10 步 = 0.2 秒）。以后网页里用鼠标推是同一回事。50 kg 的人被 150 N 推 0.2 秒，躯干速度变 0.8～1 m/s；250 N 是 1.2～1.7 m/s（力作用在上身，人会被推得前倾或后仰）。被推后 1 秒（`PUSH_GRACE`）内不按步态时钟奖励节奏，因为要乱跨几步才稳得住。评论家的特权块 `push` 是当前推力（机体系，/100 N），策略本身看不到。回放、测验载入策略时不带随机推（`policy.ENV_KEYS` 里没有推搡设置），要推就显式调 `env.push`。
- **超时 ≠ 摔倒**：超时用终止前状态的价值做 bootstrap，摔倒才当终止。开局把各环境的回合进度打散，避免同时重置。
- **学习率每轮调一次**：按最后一个 epoch 的平均 KL 调。逐小批调会塌缩（KL 相对收集时的旧策略累积，越往后越大，学习率只降不升）。
- **价值网络 PopArt 式归一化**：改统计量时同步缩放输出层，价值输出不跳变。
- **回放时用保持朝向的小控制器**：观测没有绝对朝向，策略只能保证转向速率为 0，朝向会慢慢漂（10 秒横向漂 4 米）。`export.py --hold-heading 1.5` 用转向指令把朝向拉回 0，不改策略。
- **网页必须走 http**：three.js 是 ES 模块，`file://` 会被浏览器拦。

## 身体模型
几何（尺寸、各刚体位置）沿用官方模型，回放页面不用改。`human50` 改质量、力气、活动范围、积分器，并加了脖子，由 `make_model.py` 生成，`check_body.py` 体检。

| 身高 / 体重 / BMI | 1.56 m / 40.8 kg / 16.7 | 1.56 m / 50 kg / 20.5 | BMI 18.5～24 正常 |
| 躯干占体重 | 36% | 49.7% | 49.7%（Winter） |
| 小腿 + 脚占体重 | 19% | 12.2% | 12.2% |

- **质量按段分配**：总质量 50 kg，各段按 Winter/Dempster 人体测量表，躯干再按胸 : 腰 : 胯 = 0.42 : 0.29 : 0.29 分。只改每个 geom 的密度。模型躯干偏长（髋到肩 0.52 m，真人同身高约 0.45 m），所以质心在身高 60%，比真人（约 55%）高 6 cm。
- **力气按真人比例，再加转速损失**：最大力矩 = 真人静态值（Nm/kg，`HUMAN_ISO`，取健康成年人的中间量级，不是某篇文献的精确值）× 体重，各关节之间的比例和真人一致。执行器本身在任何转速都能出满力，真人肌肉转得越快力气越小，所以每个关节加阻尼 = 最大力矩 / 肌肉速度：转到 15 rad/s 时力矩被抵消完。被迫弯曲时（落地缓冲）阻尼让阻力更大，和肌肉"离心收缩更有力"一致。
- **肌肉速度用起跳测验校准**：只改这一个参数，起跳测验结果是 8 rad/s → 7 cm、11 → 18、**15 → 48**、20 → 65、30 → 88（世界级）。不加转速损失、直接给真人静态力气会跳到 85 cm。
- **踝的力气决定站不站得稳**：踮脚尖单脚撑住全身要 50 kg × 9.8 × 0.16 m ≈ 78 Nm。官方的 20 Nm 单脚支撑时只够身体前倾 2.6°（双脚 5°），"踝策略"几乎用不上。起跳测验里踝的力气影响不大，主要靠髋和膝。
- **积分器 implicitfast**：力气和阻尼加大后，脚、手这类轻的部位在显式积分下 `dt × kv / 惯量` 超过 2 会发散（`human50` 的踝是 2.6）。implicitfast 把速度相关的力隐式处理，GPU 吞吐不变。
- **起跳测验怎么做**：站 → 下蹲 → 蹬伸 的开环动作（下蹲/蹬伸时髋膝踝目标角、脊柱前倾、用时、手臂摆幅，共 11 个参数），CEM 搜最好的一组，判据是"质心高于站立时，同时双脚都离地 15 cm 以上、身体直立"，坐着、跪着、倒地都骗不了。这是开环成绩，训练出的策略一般只会更好。
- **脖子**：转动中心在头中心下方 9 cm（头底），网页里头的造型挂在 `head` 刚体上、脖子圆柱挂在胸上，所以转头时接缝不错开。头上的第一人称相机 `egocentric` 跟着头转。
- **手臂够得到拳击姿势**：直拳在肩高正前方能伸到 0.62 m（满臂长），拳能护到下巴前（差 1 cm），两个身体相同。

## 实测结果
确定性动作，指令 1.0 m/s，6 个人形各跑 10 秒：

| 版本 | 训练轮数 | 平均前进速度 | 摔倒 |
|---|---|---|---|
| A 手臂前伸 | 1500 | 0.96 m/s | 0/6 |
| B 手臂下垂 | 800 | 0.97 m/s | 0/6 |
| C 摆臂（B 续训） | 800 + 400 | 0.96 m/s | 0/6 |
| D 大步平脚（C 续训） | 1200 + 700 | 0.93 m/s | 0/6 |

- **吞吐**：4096 环境约 12～15 万样本/秒（采 0.45 s + 训 0.27 s 每轮）。
- **学习曲线**：第 50～150 轮每个环境约 1.3 秒就摔；第 150～250 轮是"站着不倒但不往前走"（速度 0.2～0.3 m/s）；第 250 轮起稳定走满 10 秒；第 300 轮后平均 0.93 m/s，几乎不摔。B 的站稳阶段更长（第 300 轮仍 0.34 m/s，第 593 轮前后才走起来）。改手臂姿势不影响走路能力。
- **摆臂**：B 上臂 ±7°，左右不对称（右 3.8°、左 10.5°），与同侧脚相关 +0.20，是被身体带着晃；C 是 ±19°（目标 ±20°，右 20.0°、左 17.8°），与同侧脚 −0.87、与对侧脚 +0.85，即右臂和左腿一起往前。

### 阶段 1c：膝盖（2026-10-16，`runs/knee1`～`knee3`）
- **发现**：查侧移为什么跟不上时量了关节角。从换成 human50 身体起（sym2、stand3、side1～4），所有策略都是**直腿走**：往前走 0.8 m/s 时膝关节角 0～4°，用刚体位置算的大腿-小腿夹角最大约 5°；侧移、站定、倒退也一样。膝盖动作一直顶在裁剪值上，PD 目标角被裁到伸直限位 +2°。官方身体的 walk4 会弯到 37°。真人走路着地期膝盖约 15～20°，摆腿约 60°。直腿时抬脚只能靠髋和踝。推测的原因是能耗惩罚按 |力矩 × 角速度| 算，膝盖顶在限位上时角速度为 0，限位免费替它撑住体重。
- 修法：加 `knee_swing`、`knee_lock` 两项（见"设计要点 → 姿态奖励"），加动作边界损失 `--bound`（见"设计要点"）。`check_mirror.py` 确认加了两项后奖励仍严格对称（差 4e−5）。`regress.py` 加了两项指标：摆腿时屈膝（每条腿 95 分位）、着地时屈膝（平均）。stand3 分别是 −0.1° 和 −1.9°（过伸）。
- 从 `runs/stand3` 续训，配方同 stand3，只加 `knee_swing=2,knee_lock=1`：
  - `knee1`（+800，`--bound 10`）：膝盖学会弯（摆腿 36°），骨盆、两脚间距、往前走的跟踪都更好，但**站定没了**（原地踏步 111 步/分），着地比例指令失灵（不管要多少都是 0.54 左右）。快照显示从膝盖解锁那一下乱掉之后，700 轮里没恢复。弃用。
  - `knee2`（+400，`--bound 1`）：乱得轻得多（摔倒峰值 0.09%/步，knee1 是 0.7%）。站定、往前、倒退都没退步，随机换指令摔 0/1024。摆腿屈膝 32°，但着地时平均只有 1°，支撑腿还是直的；着地比例误差 0.12（stand3 0.05），打滑 9.0 cm/s（stand3 5.7）。
  - `knee3`（knee2 再 +600，`knee_lock` 1 → 3，11 分钟）：**前进、倒退、站定都没退步**（往前 0.02、倒退 0.07，站定 0 漂移、0 踏步），随机换指令摔 1/1024（stand3 2）。膝盖：摆腿 39°、着地平均 6.2°（进了真人范围，stand3 是 −0.1° / −1.9°）。骨盆侧倾 ±4.1°（stand3 5.5）、扭转 ±6.1°、两脚间距 8.8 cm、打滑 7.4 cm/s（stand3 5.7，在容差内）。
  - **唯一的退步：着地比例指令不灵了**。要 0.5 还是 0.7 都走成 0.52～0.57（stand3 要 0.7 时能到 0.67），误差 0.15。knee2 第 3250 轮就开始掉（0.62 → 0.59 → 0.60），knee3 掉到 0.57。猜测：`knee_swing` 只看步态时钟、不看脚是否真的离地，着地比例大时摆动窗口短，膝盖来不及弯到 40°，提前抬脚反而容易满足它，只损失一点 `clock`。

### 阶段 1f：摔倒后起身（2026-10-17～18，`runs/getup1`～`getup6`）
路线图上"网页互动人偶"的下一步：被推倒以后自己爬起来。用户选了**单独训一个起身策略，再和走路策略（sp2）切换**，不在 sp2 里加：sp2 的探索噪声已经塌到 0.15，加大噪声去探索起身，以前两次都把已有技能冲掉了（duty3、knee1），而且摔倒不终止以后，防推的动力也会变弱。分开训，sp2 一点不动，不会退步，所以不用跑 regress，只测交接。
- **倒地姿态库**（`make_fallen.py` → `models/fallen_poses.pt`）：从站立开始，推躯干 250～500 N（0.4 秒）加随机动作，倒下后一半保持动作、一半放松，4.5 秒后留下身体碰地、几乎不动的。两轮共 8185 个：仰躺 4858、趴 2840、侧躺 487，**坐/跪 0**（这样倒不出坐姿；策略起身时自己会经过坐和蹲）。躯干高度 0.07～0.25 m（站立 1.30）。
- **起身模式**（`env.HumanoidEnv(getup=True)`，`train.py --getup`）：90% 的开局从姿态库随机抽（朝向随机转），10% 站着开局（学站住）；身体碰地不终止，只有超时（`--ep-len 300` = 6 秒）。观测不带指令和步态时钟（78 维）。奖励（都在 `REWARD` 里，起身模式只算这些）：`getup_height`（躯干高度 / 站立）、`getup_up`（立直程度 × 高度比）、`getup_stand`（站起来以后不动 + 姿态接近默认站姿，方便交给 sp2）、`getup_air` / `getup_speed` / `getup_spin`（防止弹起来，见下）、`energy`、`action_rate`。"站起来"= `env.stood_up()`：躯干高过站立的 90%、立直、只有脚着地。
- **动作范围要放开**（`--full-range`）：默认动作裁在 ±1.5，膝盖最多只能指到弯 73°、髋屈 81°、肩够不到身前，蹲不起来。走路用不到这么大的角度，以前没暴露。起身策略每个关节各自裁到刚好够得着整个活动范围。
- **辅助力课程**（`--assist 0.6`）：起身训练时向上拉躯干，大小 = 体重 × assist；一轮里"站着"的时间比例 > 0.5 就每轮减 0.005，减到 0 为止（续训时接着检查点里的值）。回放、测验、网页里没有这个力。训练日志多两列：站着的比例、当前辅助力。
- **切换**（`combo.py`）：走 → 起身：脚以外碰地（和训练的摔倒定义一样）；起身 → 走：`stood_up` 连续 0.3 秒。环境按走路策略的设置建，再打开起身模式；走路策略的动作和它看到的"上一步动作"裁回 ±1.5。刚交接时 1 秒内不按步态时钟奖励（同被推后）。
- **测验** `test_getup.py runs/xxx/policy.pt [--walk runs/sp2/policy.pt]`：从姿态库抽 1024 个开局，量 2/3/5/8 秒内站起来（连续 0.3 秒）的比例，按仰躺/趴/侧躺分开，并报起身过程中腾空的时间、躯干速度峰值、角速度峰值（看是不是弹起来）。`--walk` 是交接测验：站起来后交给走路策略，一半让站、一半让 0.6 m/s 往前走，再跑 5 秒，数又摔倒的。

- **再试 B：手撑地给奖励**（`getup_hand`，从 getup7/8 续训，测验加"手承重"= 手碰地且躯干、胯、大腿、上臂都离地）：

  | `getup8` | 躯干低（< 站立 60%）+ 躯干离地 + 手撑地，权重 1，+1040 轮停 | 没变化：它从来不经过这个状态，奖励等于没有。仰躺手 0% |
  | `getup9` | 放宽成"坐起来（立直 > 0.3）或躯干离地"+ 手撑地，权重 2，+280 轮停 | **钻空子**：趴着的撑起上身就不起来了（手碰地 97% 的时间，8 秒内只有 3% 站起来）；仰躺还是 0% |

### 阶段 1g：移动加速（2026-10-18，`runs/sp3`、`sp4`）
用户："感觉躲球之前需要给移动加速"。先量了 sp2 起步有多快（`move_probe.py`，站 1.5 秒后突然给指令）：
- **只下指令躲不开快球**：0.5 秒内躯干只挪开 2～13 cm，0.8 秒 8～34 cm；躲开一个正对躯干的球要横着让开约 25～30 cm，14 m/s 的球从 7 米外飞来只要 0.5 秒。
- **侧移本身就慢**：指令 0.4 只走到 0.23 m/s，0.8 走到 0.45（训练只到 ±0.4，但给 0.8 也不摔）。把指令加速度上限从 1.5 放到 3 m/s²，前 0.5 秒多挪 30～70%；完全放开也只有 8～11 cm，瓶颈在策略。侧移时髋外展只用了 5～12°（关节能到 45°），每步横移约 20 cm；步频指令调高调低都不变快。
- **sp3**（sp2 +800 轮，15 分钟）：侧移 ±0.8、倒退到 -1.0、指令加速度上限 3 m/s²、新加 `--cmd-ellipse`（前进和侧移合起来限在椭圆里，侧移最快时前进为 0，不然会抽到"前进 1.2 + 侧移 0.8"这种很难的快速斜走）、换指令间隔 1～4 秒，奖励不变。结果没变快（侧移 0.22 / 0.44 m/s），前进 1.2 反而只到 0.88，没用。
- **原因**（`reward_terms.py` 奖励分项）：让 sp2 按侧移 0.8 的步子走（实际 0.51 m/s）、奖励按指令 0.4 算，每步总奖励 3.00，比它照常慢走（0.24 m/s）的 4.16 还低。走快时脚打滑（point_slip -0.11 → -0.37）、脚往外侧翻（foot_roll -0.05 → -0.26）、节奏和朝向变差，多扣的比速度跟踪多拿的还多，按现在的奖励慢慢走就是最优，再练也不会快。
- **sp4**（sp2 +800 轮，16 分钟）：sp3 的指令改动 + 新奖励 `lat_vel=3`（单独的侧移跟踪，宽的误差尺度，离得远也有梯度）+ `--cmd-grace 0.5`（换指令后 0.5 秒内不按步态时钟算节奏，同被推之后：不然起步要等时钟轮到那只脚，最多半个周期）。防打滑、防翻脚的项一项没放松。

  - 侧移 0.8 时 sp4 走到 0.65 m/s，打滑反而比 sp2 少（point_slip -0.28 vs -0.36），翻脚差不多（-0.25 vs -0.26），骨盆更平：找到了一种更干净的快侧移，不是靠放松姿态换的。

### 阶段 2a：躲球（进行中，2026-10-18，`runs/dodge1`、`dodge2`）

## 网页互动版（2026-10-18，`web/play/`）
近期目标"网页里能直接玩的人偶"的第一版：打开 `http://localhost:8765/play/index.html`（`viewer.bat` 起服务后，回放页面左上角"互动版 →"）。物理是 MuJoCo 官方的 WebAssembly 版，在浏览器里实时跑；动作全由两个训练好的策略决定（走路 `runs/sp4`（原来 `sp2`，见"阶段 1g"）、起身 `runs/getup19`，最初是 `getup7`），没有任何手写动作。
- **玩法**：WASD / 方向键走（前进速度用滑块调，按住 Shift 走快到 1.2 m/s），Q / E 转身；在人身上按住鼠标往一个方向拖，松开就朝那个方向推躯干 0.2 秒（拖 1.2 米 = 推力上限，默认 500 N，滑块可调到 800 N），拖的时候画红箭头；按钮"随机推一下"（250 N）、"推倒它"（600 N）、"慢放"（0.25 倍）、"重来"。手机上用屏幕方向键，拖人推。倒地后自动切到起身策略，状态栏变红；站稳 0.3 秒交回走路策略。

- 回放页面和互动版的人形外观共用 `web/character.js`（从 `index.html` 抽出来的，行为不变）。

- 底部工具栏："特写"对准第一个人，"全景"回默认镜头，空格暂停。默认打开最近一次导出的回放，勾选多个可同台对比（每组一段跑道）。
- **造型定型，没有调节面板**。外观参数集中在 `web/index.html` 的 `LOOK`（头、脖子、肩、胸腰胯、四肢粗细、袖长、手脚大小、描边、肤色/头发/裤子/鞋颜色），改完刷新生效。会改变物理的东西（质量、力气、关节范围、默认姿势）在 `make_model.py` 的预设和 `models/arm_pose.json`，改了必须重训；身体比例在 `models/humanoid.xml`，改了还要同步改网页造型。
- 外观（`dressCharacter`）只影响画面，物理和训练用官方胶囊体：
  - **躯干**：一张蒙皮（`torsoGeo`，`SkinnedMesh`），骨头是 `torso` / `waist_lower` / `pelvis` 三个刚体，权重过渡区跨在两个腰关节上。上半截是衣服，下摆以下是裤子。绑定姿势用这三个刚体站直时的相对位置（`SPINE_REST`，抄自 `humanoid.xml`）。
  - **四肢**：带肌肉起伏的旋转体（`limbGeo`），画到关节为止，关节处有球补缝。T 恤短袖，`LOOK.sleeve` 设 1 则盖到肘。
  - **头**：略扁的球；头发是按发际线铺的一张皮（`hairGeo`，改 `HAIRLINE` 换发型）；眼、眉、嘴是贴面小片（`decal`，不描边）；另有耳朵和鼻子。
  - **手**：带拇指的连指手套形，手臂下垂时掌心朝大腿。**鞋**：鞋面加鞋底（`shoeGeo`），鞋底贴物理脚底。
- **肩和上臂**：物理肩关节转轴离下巴只有几厘米，照画就是耸肩。视觉肩头单独定位（`LOOK.shoulderLevel` / `LOOK.shoulderSpan`，固定在躯干上），从脖子根到肩头画斜坡；上臂每帧从肩头连到肘关节（`updateLinks`），不跟物理上臂刚体走。所以肩怎么调手臂两头都不脱开，代价是上臂视觉长度随姿势变（0.25～0.33 m，物理长度 0.31 m），肩越低上臂越短。
- `show()` 用令牌防并发：加载是异步的，快速连续切换只认最后一次。

## 能力范围
`walk4`（官方身体）的指令范围是 vx∈[0.4,1.2]、wz∈[−0.3,0.3]，范围内跟得很准，范围外不行。实测（512 个人形连续执行一串指令，每段 5 秒）：

| 指令 | 实际 | 摔倒（人次） |
|---|---|---|
| vx 0.4 / 1.0 / 1.2 m/s | 0.43 / 0.97 / 1.15 | 0 |
| wz ±0.3 rad/s | +0.29 / −0.27 | 0 |
| 站定（0） | — | 395（5 秒内） |
| vx 1.6 m/s | 只到 1.22 | 137 |
| wz 0.8 rad/s | — | 159 |

- 不会侧移、倒退。
- 步态不是动捕：摆臂是按时钟画的正弦，偏机械；步态周期固定 1.1 秒（真人走快时步频会变）。要更自然需引入动捕参考（DeepMimic/AMP）。
- 回放是 1 m/s 直走：`export.py` 的指令固定（`--cmd`），默认的 `--hold-heading` 会覆盖转向指令。

**近期目标（2026-10-16 定）：网页里能直接玩的人偶**。打开网页，用鼠标推它、扔球砸它、拖指令让它走，它会踉跄、站稳、躲开。物理用 MuJoCo 官方的 WebAssembly 版（和训练是同一个引擎），策略网络在浏览器里算。远期目标太远、用处不直观，先做一个做完就能玩的成品。顺序：被推不倒（sp2 基本做到，见"阶段 1d""阶段 1e"；着地比例先放着，以后再调）→ 摔倒后起身（`runs/getup19` 手撑地 + 切换，见"阶段 1f"）→ 网页互动版（第一版完成，见"网页互动版"）→ 加发球机（躲避球的雏形，2026-10-18 雏形完成：4 种球、按弹道瞄准、命中统计）。

**做不到或很贵的**（2026-10-14 确认）：
- 手是实心球，没有手指和手腕，抓、扔、接都做不了。以后用"吸附"：手碰到球时用约束把球粘住，松手时解除，不改人的身体。
- 视觉能做但贵：实测 4096 个人形同时渲染第一人称 32×32 深度图每帧 3.6 ms、64×64 RGB 每帧 12.4 ms（一步物理约 15 ms）；贵在从像素学，样本效率低。先直接给真实位置，需要时加视野和遮挡判断，最后才考虑像素（用"看真实位置的策略"带"看画面的策略"）。
- 受伤、疲劳、击倒不在物理里，只能用规则定义；没有声音模拟。
- 策略没有记忆。需要记忆时用可扩展输入加"最近几步的历史"。读对手、佯攻是博弈，成本最高。
- 没有动捕时动作只能靠奖励塑形，偏机械。多人团队躲避球太贵，一个人对发球机或一对一可以。
- 走迷宫：地图已知时用寻路算法给路点、策略只管走（和"到点 + 绕障碍"同一类）；地图未知要边走边探索时，用光线投射测墙的距离，记地图和选方向交给程序，策略只管走。纯强化学习探索大迷宫很慢。


## 约定和注意
- 加障碍物（墙、箱子、台阶）前要改 `env.ground_contact`：现在世界上所有固定物体都算"地面"，手扶墙也会判摔倒。要把地面（可以踩）和墙/障碍分开。
- 坐标：MuJoCo Z 轴朝上、四元数 wxyz；three.js Y 轴朝上、xyzw。网页把整个机器人放进一个绕 X 轴转 −90° 的组里处理。
- MuJoCo 用 `fromto` 定义的胶囊，几何体 z 轴从 `to` 指向 `from`（朝身体近端），不是朝远端。网页用 `ends()` 按"离关节近的一端"判断方向，不依赖轴向。
- 导出里 `vx_hist` 的形状是 `[时间, 世界]`。
- 看 `.venv\Lib\site-packages\...` 的包源码时用绝对路径，不要 `cd` 进去，否则后续脚本会在错误的工作目录运行。
